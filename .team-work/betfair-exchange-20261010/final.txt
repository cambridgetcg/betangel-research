### 0.2 Threat model (the docs must state this)
The order path is built to stop these:
- accidental or unattended live orders from agents, scripts, cron, CI, cloud hosts, the wrong checkout or the wrong working directory;
- orders priced off stale or forged market data;
- double bets after an unknown outcome;
- risk caps being reset because local state was lost;
- secrets leaking into files, logs or exceptions.

It does **not** stop a deliberately malicious process running as Yu's macOS user. Such a process can approve a Keychain dialog, fake a pty or edit the Python. Operator-presence checks (typing on a tty, the Keychain dialog) slow down automation. They are not cryptographic proof that Yu was there.

### 0.3 What live safety rests on
1. Paper mode is the default. Live mode needs an explicit `--mode live` on every command **and** arming in the config.
2. There is one choke point, `gateway.py`. Each capability is bound to the sha256 of the exact request body bytes. The transport refuses any JSON-RPC call that is not a read unless it carries that matching digest.
3. Before every live order, Yu must retype it on `/dev/tty`.
4. Each Mac has one fixed state root outside every git worktree. The kill file and the gateway lock are global. A journal anchor is kept in the Keychain. Every live start reconciles against the exchange.
5. The journal is append-only and hash-chained. Each record is committed with `F_FULLFSYNC` before any byte goes to the network.
6. An unknown outcome is never treated as zero. Orders in UNKNOWN, ABSENT_UNCONFIRMED or a provisional replace child count at full adverse exposure and block new placement until resolved. Nothing is ever resent automatically.
7. In live mode the gateway fetches its own market data with the live key, immediately before the risk check. It never trusts a book supplied by the caller.

### 0.4 Style
- Follow the repository's existing style:
  - Records are plain dicts with exact key sets, each with a `validate_*` function.
  - Classes are used only for stateful components.
  - No dataclasses, no TypedDict, no `logging`.
  - Standard library only, with relative imports.
- Bad input raises `ValueError` or a subclass of it.
- Status strings are snake_case and say how much they prove.
- Python 3.10 compatibility is enforced by a test (§14). Do not use `tomllib`, `datetime.UTC`, `hashlib.file_digest`, `typing.Self` or `except*`.
- Type hints in this spec are documentation only. Use `typing.Iterator`, never a lowercase `iterator`, or leave the hint out.

### 0.5 How the critiques were handled
**Accepted in full:**
- Safety: 2, 4–10, 12–14, 16–31.
- API correctness: 1–21.
- Repo fit: 1–5, 7–22.

**Accepted with changes:**
- **Safety 1.**
  - Accepted:
    - a per-order typed echo on `/dev/tty`;
    - the confirmation token can no longer come from an environment variable;
    - the `arm-token` command is removed;
    - the live app key is stored with `-T ""` (its effect is checked in T0).
  - **Rejected:** the HMAC and nonce token. Its key, `config_sha256`, is public, so it adds no secrecy. Single-use presence already comes from the per-order echo.
  - The token stays as a per-day friction value, supplied through `--confirm-live` only.
- **Safety 3 / repo-fit 1.**
  - Accepted: a fixed state root outside every worktree.
  - Changed: it is keyed by `<profile>`, not `sha256(username)`, because the kill file and the HALT must work before any Keychain read.
  - Cross-profile protection comes from three things: a global `KILL` file, a global `.gateway.lock`, and an account fingerprint registry (`accounts.json`) that refuses a second profile for the same account.
- **Safety 11.** The transport check is an allowlist: read methods pass, and everything else needs a digest-bound capability. A regex like `(?i)Orders|Heartbeat` would also catch `listCurrentOrders` and `listClearedOrders`.
- **Safety 4 (A15, now A19 `ref_roundtrip_verified`).** Accepted, with one exception: `live-probe` is the only command that can establish this marker, so it is exempt from it.
- **Safety 9 and API 4, merged.**
  - Normal commands may make 30 successful logins per 10 minutes, with a ceiling of 60.
  - `kill`, `cancel` and `reconcile` skip that cap.
  - Every command still respects the persisted ban and the limit of 2 consecutive login failures.
- **Repo-fit 6.**
  - No implementer unit edits shared files.
  - The patch in §16 is prepared as one isolated commit, S0. The coordinator applies it only after Yu and Codex agree.
  - Merging the betfair code without S0 is forbidden, and the handoff file records that gate.
  - README edits stay in one final commit, made after rebasing.
- **Repo-fit 7 / safety 20.**
  - Removed: `frozen_experiment`, `allowed_experiments` and the `bx-*` strategy refs.
  - Kept: the programmatic `OrderGateway` API with `source="api"`, but **only in paper mode**. This is what the "programmatic API for future frozen experiments" requirement asks for.
  - Live programmatic use is refused in v1. Allowing it would need an AGENTS.md change that Yu approves.
- **API 14(a).** Depth below 3 uses the conservative multiplier `max(depth, 3)/3`.
- **Repo-fit 11.**
  - Property tests default to 40 seeds × 120 steps.
  - The pre-merge run uses `BETANGEL_BETFAIR_PROPERTY_SEEDS=300` and `BETANGEL_BETFAIR_PROPERTY_STEPS=200`, and the report records the seed count and wall time.

**Rejected outright:** nothing beyond the HMAC token.

- The `--state-root` and `--config` flags, and the in-process `deps["home"]`, work **only** when `BETANGEL_BETFAIR_FORBID_NETWORK=1` is set. That variable is the test harness, so whenever these overrides work, the network is off too.


**Rules for `HttpTransport.request`, in this order:**
1. If `env["BETANGEL_BETFAIR_FORBID_NETWORK"] == "1"`, raise `TransportError(phase="preflight", code="network_forbidden", may_have_arrived=False)` before anything else.
2. The URL must be `https`, use no explicit port or port 443, have a host in `allowed_hosts` (from `hosts_for`), and have a path in `constants.ALLOWED_PATHS`:
   - `/api/certlogin`, `/api/login`, `/api/keepAlive`, `/api/logout`;
   - `/exchange/betting/json-rpc/v1`, `/exchange/account/json-rpc/v1`.

   Anything else raises `TransportError(code="url_not_allowed")` during preflight. This makes the Heartbeat API path impossible to call.
3. **Digest gate for the two JSON-RPC paths.** The body must parse as a JSON object (batch arrays are refused) with a string `method`.
   - If `method ∈ constants.READ_METHODS`, then `order_digest` must be `None`.
   - Otherwise:
     - the path must be the betting path;
     - `order_digest == bytes_sha256(body)` must hold;
     - `idempotent` must be False.

     If any of these fails, raise `TransportError(phase="preflight", code="unbound_rpc_refused")`.
4. Never send `Expect: 100-Continue`. Send `Accept-Encoding: gzip` and `Connection: keep-alive`. Decode gzip/deflate with a bounded `zlib.decompressobj` (`max_length`). Exceeding `max_response_bytes` raises `code="response_too_large"`.
5. Any 3xx status raises `TransportError(phase="receive", code="redirect_refused")`. Redirects are never followed.
6. **Deadline.** `deadline_s` covers connect, send and every read. Before each socket operation, set `sock.settimeout(remaining)`. When it runs out, raise `code="deadline_exceeded"`.
7. **Non-idempotent calls:**
   - Set `conn.auto_open = 0`.
   - If the connection is closed, or has been idle for at least `idle_reconnect_s`, reconnect explicitly *before* writing.
   - Wrap the socket with a byte counter. `may_have_arrived = bytes_written > 0`.
   - Never resend.
8. **Idempotent calls (reads only):** retry once on `RemoteDisconnected`, `BrokenPipeError` or `ConnectionResetError`, but only if no response byte was received.
9. Exception text never contains headers, the body or the URL query string.

**`open_stream_socket`:**
- Same network-forbidden check.
- Host must be in `constants.STREAM_HOSTS = {"stream-api.betfair.com", "stream-api-integration.betfair.com"}`, port 443.
- Uses `ssl.create_default_context()` with TLS ≥ 1.2, `check_hostname=True`, then `wrap_socket(server_hostname=host)`.

**`make_tls_context`:**
- `ssl.create_default_context()`, `minimum_version = TLSv1_2`, `check_hostname=True`, `CERT_REQUIRED`.
- Calls `load_cert_chain(certfile, keyfile, password=passphrase.reveal() if passphrase else None)` when a certificate is given.

## 3. Shared record schemas

### Book snapshot (I7)
Keys are exact.
```json
{"market_id":"1.234","source":"rest_listMarketBook|stream_cache|recording|fixture",
 "fetched_by":"gateway_self_fetch|read_command|stream_cache|recording|fixture",
 "key_type":"delayed|live|historical|synthetic","app_key_slot":"delayed|live|null",
 "observed_at":"...ffffffZ","monotonic_ns":123|null,"pt":1700000000000|null,
 "status":"OPEN|SUSPENDED|CLOSED|INACTIVE","inplay":false,"version":4249587130|null,"bet_delay":0,
 "is_market_data_delayed":true|false|null,"catalogue_present":true,
 "market_time":"2026-10-10T14:30:00.000Z"|null,"number_of_winners":1|null,
 "betting_type":"ODDS"|null,"market_type":"WIN"|null,"event_type_id":"7"|null,"price_ladder_type":"CLASSIC"|null,
 "invalid_reason":null|"non_finite_size"|"catalogue_missing",
 "runners":{"12345":{"status":"ACTIVE","handicap":0.0,"ltp":3.5|null,
   "back":[[3.5,120.0],[3.45,40.0]],
   "lay":[[3.55,80.0]],
   "traded":{"3.5":1520.4}|null,
   "total_matched":null}}}
```
- `back` is availableToBack, best (highest price) first. `lay` is availableToLay, best (lowest price) first. `traded` is cumulative volume at each price, as published.
- Where the REST fields come from (§7): `market_time`, `betting_type`, `market_type`, `event_type_id` and `price_ladder_type` come from the catalogue row. `number_of_winners` comes from MarketBook.
- With no catalogue row, those fields are `null`, `catalogue_present` is false and `invalid_reason` is `"catalogue_missing"`.
- In the stream, the ladder type is read with `book.ladder_type()`, which accepts the value either as an object with a `type` key or as a string.
- Non-finite sizes become `null`, and `invalid_reason` is set to `"non_finite_size"`.

### Instruction v1 (I8)
Only plain LIMIT orders are supported.
```
{"selection_id": int>0, "handicap": 0, "side": "BACK"|"LAY", "price_h": int (on ladder), "size_p": int>0, "persistence_type": "LAPSE"}
```
On the wire this becomes `{"orderType":"LIMIT","selectionId","handicap":0,"side","customerOrderRef","limitOrder":{"size": size_p/100,"price": price_h/100,"persistenceType":"LAPSE"}}`.

```
{intent_id, customer_order_ref, customer_ref, customer_strategy_ref, mode, market_id, selection_id, handicap, side,
 price_h, size_p, persistence_type, state, bet_id|null, size_matched_p, average_price_matched_h|null, size_remaining_p,
```

Paper and live use the same shape.
```
{status: SUCCESS|FAILURE|PROCESSED_WITH_ERRORS|TIMEOUT, error_code|null, market_id,
```

- There is **no** `orders.mode` key. Mode comes only from `--mode` on the CLI.

## 5. Credentials and Keychain

Services are compiled in. The Keychain account field is `<profile>`.

| Service | Contents | Needed for |
|---|---|---|
| `betangel-research.betfair.username` | Betfair username | login |
| `betangel-research.betfair.password` | Betfair password | login |
| `betangel-research.betfair.app-key.delayed` | Delayed app key | read path and recorder |
| `betangel-research.betfair.app-key.live` | Live app key, created with `-T ""` | live orders only |
| `betangel-research.betfair.cert-key-passphrase` | optional | encrypted `client-2048.key` |
| `betangel-research.betfair.journal-anchor` | **non-secret** JSON `{genesis_sha256, seq, last_sha256, updated_at}` | live journal anchor (§9.9) |

**Reading a secret:**
- Runs `/usr/bin/security find-generic-password -s <service> -a <profile> -w`.
- Uses the absolute path, `env=minimal_env()`, `capture_output=True` and a 120 s timeout. The timeout allows time to answer a Keychain dialog.
- The argv contains only service and account names.
- A non-zero exit raises `CredentialError("keychain_item_unavailable:<kind>") from None`.
- stdout and stderr are never kept. No exit code is interpreted.

**`keychain-setup`** prints commands and never runs them. `-w` is always the last token, so `security` prompts for the value:
```
security add-generic-password -U -s betangel-research.betfair.username -a default -w
security add-generic-password -U -s betangel-research.betfair.password -a default -w
security add-generic-password -U -s betangel-research.betfair.app-key.delayed -a default -w
security add-generic-password -U -s betangel-research.betfair.app-key.live -a default -T "" -w
```
The man page does not document `-T ""`. The intent is that no application is trusted, so every read of the live key raises a macOS authorization dialog. The operator clicks **Allow**, never **Always Allow**. T0 records whether this actually happens. Arming does not depend on it, because it cannot be detected.

**Certificate and key:**
- Files live outside every git worktree. The default is `~/.config/betangel-research/betfair/`.
- The key must have no group or world permission bits.
- The docs recommend encrypting the key (`openssl rsa -aes256`) and storing its passphrase in the Keychain.
- The `.crt` is uploaded by hand at `https://myaccount.betfair.com/accountdetails/mysecurity?showAPI=1`.

**What the code never does:**
- persist session tokens (each CLI run logs in once and logs out at the end; the recorder keeps its token in memory only);
- log headers, login bodies, tokens, usernames or app keys;
- write anything without `refuse_forbidden` plus `assert_clean`;
- store `errorDetails` or `sourceIdKey`.

**Tests:** every test injects `keychain_runner` or `loader`. No test may call the real `/usr/bin/security` (§14).

## 6. Auth and session behaviour

**Certificate login (the default):**
- `POST https://identitysso-cert.<tld>/api/certlogin`.
- Headers: `X-Application: <app key>` and `Content-Type: application/x-www-form-urlencoded`.
- Body: `urllib.parse.urlencode({"username": u, "password": p}).encode("ascii")`.
- The TLS context carries the client certificate, and certificate verification stays on. Betfair's sample uses `-k`; we do not.
- Success is `{"sessionToken", "loginStatus": "SUCCESS"}`. Any other `loginStatus` raises `AuthError(status)`.
- Login status codes are not secret and may be logged.

**Interactive login (fallback):**
- `POST https://identitysso.<tld>/api/login` with `Accept: application/json` (mandatory), `X-Application` and the same form body.
- The response is `{token, product, status, error}`.
- `LIMITED_ACCESS` gives a token but `can_bet=False`.
- `LOGIN_RESTRICTED` and `FAIL` raise.
- `STRONG_CODE_FAIL`, `TEMPORARY_BAN_TOO_MANY_REQUESTS` and `MULTI_FACTOR_AUTHENTICATION_REQUIRED` are matched on the `error` field whatever the `status` says.

**keepAlive and logout:**
- `<sso>/api/keepAlive` and `<sso>/api/logout`, with `Accept: application/json`, `X-Authentication` and `X-Application`.
- The HTTP method comes from `session.sso_http_method` (default POST; F08 is unresolved, see T2).
- Success requires `status == "SUCCESS"`. A missing or empty `error` is not an error.
- On keepAlive `NO_SESSION`:
  1. journal or ledger a `session_shorter_than_configured` note;
  2. halve the interval for this process (minimum 60 s);
  3. `invalidate_and_relogin()` once.

**Login protection.** Everything is persisted in `auth/login-ledger.jsonl`.
- **Successful-login cap.** If `max_successful_logins_per_10min` successful logins happened in the last 600 s, `login()` refuses with `LoginBudgetExceeded`. `emergency=True` skips this cap; `kill`, `cancel` and `reconcile` use it.
- **Consecutive failures.** After `max_consecutive_failed_logins` failures in a row with no success between them, every login is refused with `AuthError("login_failures_need_operator")`, including emergency logins. The `login-reset` command, which needs a tty echo of `RESET LOGIN FAILURES`, appends a reset row and clears this.
- **Ban.** `TEMPORARY_BAN_TOO_MANY_REQUESTS` writes a row with `ban_until = now + ban_lockout_s`. Until then `LoginBanned` is raised for every caller, across restarts.
- **Relogin on invalid session.** `INVALID_SESSION_INFORMATION` or `NO_SESSION` on a read or stream call triggers exactly one relogin in that call chain. Order calls never relogin and resend (§9.4).

**Bet Angel coexistence.** This runs before any login, in the CLI. When `coexistence.bet_angel == "unverified"`, every command that logs in needs `--bet-angel-paused`. That flag is the operator stating that Bet Angel is logged out or not managing positions. It is recorded as `coexistence_ack: true` in the ledger row. Without it the command exits 2 with `bet_angel_coexistence_unverified`.

**Hosts** (`hosts_for`). The stream host for every jurisdiction is `stream-api.betfair.com:443`.

| Jurisdiction | SSO | Cert SSO | API |
|---|---|---|---|
| com | identitysso.betfair.com | identitysso-cert.betfair.com | `api_host` (default api.betfair.com; NZ must set api.betfair.com.au) |
| com.au | identitysso.betfair.com.au | identitysso-cert.betfair.com.au | api.betfair.com (AU unverified) |
| it | identitysso.betfair.it | identitysso-cert.betfair.it | api.betfair.com |
| es | identitysso.betfair.es | identitysso-cert.betfair.es | api.betfair.com (use the visible .es text; the page's .it links are a docs bug) |
| ro | identitysso.betfair.ro | identitysso-cert.betfair.ro | api.betfair.com (unverified) |

## 7. Read path behaviour

**Transport:**
- JSON-RPC `POST https://<api>/exchange/betting/json-rpc/v1` for betting and `/exchange/account/json-rpc/v1` for accounts.
- Body: `{"jsonrpc":"2.0","method":"SportsAPING/v1.0/<op>"|"AccountAPING/v1.0/<op>","params":{...},"id":<int>}`. No batching.
- Headers: `X-Application`, `X-Authentication`, `Accept: application/json`, `Content-Type: application/json`, `Accept-Encoding: gzip`, `Connection: keep-alive`.

**Which app key is used:**
- Read subcommands use `read.app_key_slot`, default `delayed`.
- In live mode the gateway's `JsonRpcClient` and its `ReadClient` both send the **live** key. A session token works with either key, because `X-Application` is set per request.

**Error parsing (`parse_rpc_response`), in order:**
1. Parse the body as JSON whatever the HTTP status. If it cannot be parsed, the error is `ApiError(surface="dsc", code="DSC-xxxx")` if a DSC fault code can be found, else `(surface="http", code="HTTP_<n>")`.
2. If `error` is present:
   - read `error.data[error.data.exceptionname]` (an `APINGException` or `AccountAPINGException`);
   - otherwise search `error.data` recursively for a dict containing `errorCode`;
   - keep `requestUUID`;
   - **never** keep `errorDetails`.
3. If there is no `errorCode` and `error.code == -32099`, the code is `error.message` (`ANGX-00nn`) with surface `angx`, which classifies as `unrecognized`.
4. If there is no `errorCode`, fall back to the numeric `error.code` in {−32700, −32601, −32602, −32603} with surface `jsonrpc`.
5. If `result` is present, return it.

**Weight planner** (200-point limit):
- **Book weights:** none=2, SP_AVAILABLE=3, SP_TRADED=7, EX_BEST_OFFERS=5, EX_ALL_OFFERS=17, EX_TRADED=17.
- **Normalise first:** `EX_ALL_OFFERS` overrides `EX_BEST_OFFERS`.
- **Combinations:** EX_BEST_OFFERS+EX_TRADED=20 and EX_ALL_OFFERS+EX_TRADED=32 replace the sum of those two components. Other components are then added.
- **Depth override:** multiply the **total** by `max(depth, 3)/3`.
- **Catalogue weights:** MARKET_DESCRIPTION=1, RUNNER_METADATA=1, all others 0.
- **Chunk size:**
  - weight > 0: `min(floor(200/weight), 250)` ids;
  - weight 0: limited only by the 250-id cap or `maxResults`.
- **Catalogue limits:** `list_market_catalogue` refuses `max_results > min(1000, floor(200/w))` when w > 0, and refuses `max_results > 1000` otherwise.
- **Never sent:** `sort="RANK"`.
- `TOO_MUCH_DATA` and `REQUEST_SIZE_EXCEEDS_LIMIT` raise as planner bugs and are never retried.

**Catalogue join and cache:**
- `market_snapshot(market_id)` loads `catalogue-cache/<id>.json`. If the file is missing or older than `catalogue_cache_max_age_s`, it calls `listMarketCatalogue(filter={"marketIds":[id]}, marketProjection=["MARKET_DESCRIPTION","RUNNER_DESCRIPTION","EVENT_TYPE","MARKET_START_TIME"], maxResults=1)` and caches the result through `atomic_write_json`.
- Field mapping:
  - `betting_type ← description.bettingType`
  - `market_type ← description.marketType`
  - `price_ladder_type ← description.priceLadderDescription.type`
  - `market_time ← description.marketTime`
  - `event_type_id ← eventType.id`
  - `number_of_winners ← MarketBook.numberOfWinners`
- CLOSED markets are absent from the catalogue (F70). Cached rows are kept for settlement.

**OPEN and CLOSED markets.** If ids are missing from a multi-id `listMarketBook` response, each missing id is re-requested alone. A single-id CLOSED response is the source of runner WINNER/LOSER results for settlement.

**Throttles.** These are counters only; the code is single-threaded.
- At most `max_book_calls_per_second_per_market` (default 4, below Betfair's 5) calls per market id, in a sliding 1 s window. A call that would exceed it sleeps on the injected clock.
- At most 2 in flight per account across `listMarketBook` with an order projection, `listCurrentOrders` and `listMarketProfitAndLoss`. Betfair's limit is 3, and its two documents disagree on whether queued or executing requests count.
- At most 2 in flight for `listClearedOrders`.

**Retry (reads only):**
- Categories `unknown_outcome` and `rate_limited`, plus transport errors, are retried with backoff [1, 4, 16] s, 3 attempts in all.
- `session` gets one relogin and one retry.
- Never retried: `planner_bug`, `terminal_account`, `terminal_input`, `app_key`, `unrecognized`.

**Other rules:**
- `list_cleared_orders` requires `settled_from_utc`. `groupBy` is sent only when the status is SETTLED.
- `list_current_orders` uses `dateRange={"from","to"}` with `orderBy`. The legacy `placedDateRange` is never used.
- `get_account_details` returns only `{currencyCode, countryCode, discountRate, pointsBalance}`. No names are ever returned, printed or written.
- Read subcommands print `{"status":"betfair_read_response_personal_use_not_for_redistribution","key_type","app_key_slot","request_started_at","received_at","result"}`.
- `--out` writes `response.json` and `receipt.json` (sha256, clocks, key_type, code_sha256, config_sha256) under `read.out_root`, which defaults to `profiles/<p>/reads/`.

## 8. Stream client and recorder

### 8.1 Protocol state machine (`esa.py`)

**Connection sequence:**
`DISCONNECTED → CONNECTING → AWAIT_CONNECTION (op=connection, at most 15 s) → AUTHENTICATING → AUTHENTICATED → SUBSCRIBING → STREAMING → CLOSED`

**Framing:**
- Outbound lines are `json.dumps(msg, separators=(",",":")).encode() + b"\r\n"`.
- Inbound reads are buffered `recv(65536)`, split on `b"\n"`, with one trailing `b"\r"` removed.
- A line longer than `max_line_bytes` raises `StreamError("line_too_long")`.
- Lines are parsed with `json.loads`, which accepts the bare `Infinity` token.

**Authentication:**
- The message is `{"op":"authentication","id":n,"appKey":...,"session":...}`. It is written straight to the socket. It is never returned, logged or included in exception text.
- The client waits for a `status` message with the matching id and stores `connectionsAvailable`.
- `statusCode=FAILURE` raises `StreamError(code, connection_closed)`.

**Subscriptions and clocks:**
- Request ids come from a monotonic int32 counter.
- A subscribe message always sends `"segmentationEnabled": false`.
- Change messages whose `id` differs from the active subscription id are dropped and counted.
- The active subscription message is stored exactly.
- `initialClk` and `clk` are updated from every message where they are non-null.

**Liveness:**
- Before the first change message, the timeout is 2 × the requested `heartbeatMs`.
- After it:
  - `conflate_ms_echoed in (None, 0)`: timeout = `2 × heartbeat_ms_echoed`;
  - otherwise: timeout = `conflate_ms_echoed + 2 × heartbeat_ms_echoed`.
- A timeout raises `StreamError("liveness_timeout")`.
- `status: 503` is counted and does not disconnect.

**Errors:** see §11 for the `stream_status` surface.

**Reconnect:** backoff follows `reconnect_backoff_s` with ±20% jitter from an injected RNG, capped by `max_reconnects_per_hour`.

**INVALID_CLOCK:** drop the clocks and take a fresh image. This is used only by the future order-stream path, because the recorder never resumes with clocks.

### 8.2 Recorder policy
- **Sessions and segments.** One session is one invocation. One segment is one subscription. Every new subscription starts a new segment with a fresh `SUB_IMAGE`, and the recorder never resubscribes with clocks. So every segment file can be replayed on its own.
- **Choosing markets before each segment (subscription-limit protection):**
  1. `ids = market_lister(to_rest_market_filter(f, start_from_utc=now−1800 s))`. This uses the delayed key, `maxResults` 1000 and FIRST_TO_START.
  2. If `len(ids) <= recorder.max_markets` and `len(ids) < 1000`: use the coarse stream filter `to_stream_market_filter(f)` (`subscription_mode="coarse"`).
  3. Otherwise: use `marketIds = ids[:max_markets]` (`subscription_mode="explicit"`).
  4. Record the requested count and `requested_market_ids_sha256` in the segment receipt.
- **Refresh.** Every `refresh_s`, recompute the list and send a new subscription on the same connection. A subscription replaces the previous one; it is not additive. The current segment closes with gap reason `scheduled_refresh`, and the new segment starts at the new `SUB_IMAGE`. Messages for the superseded id are dropped and counted.
- **`SUBSCRIPTION_LIMIT_EXCEEDED`.** Stop the session with reason `subscription_limit_exceeded`, write the receipt, log out. Never retry the same set.
- **Line acceptance before writing** (`line_acceptance`):
  - `op == "mcm"`;
  - the line's `id` equals the active id;
  - `pt` is an int and not a bool;
  - `pt >= previous pt`;
  - `segmentType is None`;
  - `b"\r"` does not appear in `raw`.

  Handling of failures:
  - `not_mcm` and `superseded_id` lines are not written to the segment. Status and connection messages go to `events.jsonl`.
  - Any other failure (`pt_not_int`, `pt_regression`, `segmented`, `carriage_return`) closes the segment with that reason as the gap reason, writes `{"rejected_line_sha256","reason","pt"}` to `events.jsonl`, and reconnects.
- **Written lines** include `ct=HEARTBEAT` lines, `con:true` lines and `status:503` mcm lines.
- **Gaps.** The time between segments is recorded as a gap. Nothing is forward-filled.
- **Stopping.** `max_duration_s`, `max_seconds` (from the CLI), `max_bytes` (stops; never deletes), SIGTERM and SIGINT each close the segment, write the receipt and log out.
- **Key policy:**
  - `stream.app_key_slot` must be `delayed` unless `recorder.allow_live_key` is true. The docs explain that Betfair does not permit read-only use of the live key.
  - The delayed key is conflated to 180000 ms (F44/F51). The receipt labels the data `delayed_conflated`. The docs state that this data cannot support features finer than 180 s, and that the motif pipeline will mark such records as stale.
- **Housekeeping:** the lock is `recordings/.recorder.lock`. `session.maybe_keep_alive()` runs in the read loop.
- **Progress output.** `emit()` sends compact JSON lines (`sort_keys=True`, `flush=True` in the CLI): `segment_opened`, `segment_closed`, `heartbeat_at` every 60 s, `gap`, `stopped`.

### 8.3 Files in `<recordings_root>/<session_id>/`
`session_id` is `rec-YYYYMMDDTHHMMSSZ-<8 hex>`. The directory must not already exist.
- `seg-NNN.jsonl`: each accepted raw mcm line byte-for-byte, terminator stripped, followed by `\n`. There are no blank lines, so line *n* of the file is line *n* as counted by `stream.messages()`.
- `seg-NNN.recv.jsonl`: one row per segment line, `{"line","byte_offset","bytes","sha256","received_at","monotonic_ns","pt","clk"}`.
- `events.jsonl` contains, each with `at` and `monotonic_ns`:
  - `connected{connection_id}`
  - `auth_status{status_code,connections_available}`
  - `subscribed{segment,request_id,subscription_mode,market_filter,market_data_filter,segmentation_enabled:false,requested_count}`
  - `echo{heartbeat_ms,conflate_ms}`
  - `status_message{id,status_code,error_code,connection_closed}`
  - `rejected_line{...}`
  - `disconnected{reason}`
  - `gap{after_segment,from_received_at,to_received_at,reason}`
  - `segment_closed{segment,sha256,bytes,lines}`
  - `stopped{reason}`
- `receipt.partial.json` is rewritten atomically at each segment close. `receipt.json` is written atomically when the session closes. After a crash only the partial receipt exists, with `"complete": false`.

### 8.4 Receipt (`schema_version` 1)
```json
{"schema_version":1,"status":"betfair_stream_recording_not_profitability_evidence","complete":true,
 "session_id":"...","created_at":"...","closed_at":"...","data_kind":"betfair_exchange_stream",
 "key_type":"delayed","endpoint":"stream-api.betfair.com:443",
 "data_freshness":{"conflate_ms_requested":null,"conflate_ms_echoed":180000,"heartbeat_ms_echoed":5000,
```

## 9. Order path

### 9.1 Modes
- **`paper` (default):**
  - The gateway is built with `rpc=None`, so it structurally cannot reach any order endpoint.
  - Books come from a snapshot file, a recording, or a delayed-key read fetch, which makes read calls only.
  - The programmatic API (`source="api"`) is allowed.
- **`live`:**
  - Every command must pass `--mode live` explicitly, and `orders.live.armed` must be true.
  - The CLI default is `paper`. Config alone can never select live mode.
  - `source="cli_manual"` is the only source allowed.
  - Paper and live journals are separate files.
  - `MODE=LIVE` is printed to stderr before every prompt.

### 9.2 Live arming
Each failure has a code. Every failure is listed, not just the first.

### 9.3 The single choke point
**Live place, step by step:**
1. The CLI parses its arguments. Money and prices are parsed by `ticks.parse_money` and `parse_price`; `nan`, `inf`, `1e1` and values ≤ 0 are refused.
2. Run `static_arming`. If anything fails, refuse and exit 2.
3. Ask the operator to confirm: `confirmer.confirm_line(order_echo_line(...), banner="MODE=LIVE ...")`. Append an `operator_confirm` event.
4. `gateway.open()`:
   - take the global `.gateway.lock` and hold it for the process lifetime;
   - verify the journal and check the anchor;
   - in the fold, move SUBMITTING orders to UNKNOWN (`crash_between_submit_and_report`);
   - log in;
   - check the account registry;
   - run `startup_reconcile` (§9.9);
   - run `reconcile_unknown` for each UNKNOWN order (bounded time).
5. Self-fetch the book: `read.market_snapshot(market_id, fetched_by="gateway_self_fetch")` with the live key.
6. Run `dynamic_arming`, then `validate_place` and `guard.evaluate_place` (§10). If refused, journal `intent` and `risk_decision(refused)` and exit 2.
7. Build the params (below). `prepared = rpc.prepare_order(PLACE_METHOD, params)`.
8. `cap = guard.issue(decision, prepared, now_monotonic_ns=...)`. TTL 5 s, bound to `prepared["body_sha256"]`.
9. Journal `submit` with the body sha, refs, decision id and params. It is committed with `F_FULLFSYNC`.
10. Re-check `kill_engaged(paths)` (fail-closed). If engaged, journal `halt`, consume nothing and send nothing. The order becomes `REFUSED(kill_engaged_after_submit_journal)`.
11. Block SIGINT and SIGTERM with `signal.pthread_sigmask`.
12. `rpc.send_order(cap, prepared)`.
13. Journal `report`, or `report` with an exception outcome.
14. Unblock the signals.
15. Classify and transition (§9.4). If anything is UNKNOWN, reconcile.
16. Re-check the kill file. If it is engaged, cancel every order this process just placed by betId.
17. In `close()`: `anchor_write`, release the lock. The CLI then logs out.

**Rules for the step-5 book:**
- In live mode, the `book=` argument must be None (`book_source_not_allowed_live`), and the CLI refuses `--book` with `--mode live`.
- If the operator's confirmation took longer than `max_book_age_s`, the book is fetched again before evaluation. The confirmation covers market, selection, side, price and size. `marketVersion` comes from the fresh book.

**Which strings live where:**
- `gateway.py` alone contains `PLACE_METHOD = "SportsAPING/v1.0/placeOrders"`, `CANCEL_METHOD` and `REPLACE_METHOD`.
- `updateOrders` and `HeartbeatAPING` appear nowhere (boundary test).
- The transport digest gate (§2.10) refuses every non-read JSON-RPC body that is not bound by a consumed capability.

**Place request params (v1):**
```
{"marketId", "customerRef": make_customer_ref(), "customerStrategyRef": orders.customer_strategy_ref,
 "marketVersion": {"version": book.version},
 "instructions":[{"orderType":"LIMIT","selectionId","handicap":0,"side","customerOrderRef",
                  "limitOrder":{"size","price","persistenceType":"LAPSE"}}]}
```
- Never sent: `async`, `timeInForce`, `minFillSize`, `betTargetType`, MOC/LOC orders.
- **Cancel:** `{"marketId","customerRef","instructions":[{"betId","sizeReduction":null|x}]}`. Bet ids must be ours (`validate_cancel`). There is no `allow_foreign`.
- **Account-wide cancel** (killswitch only): `{"customerRef"}` with no `marketId` and no `instructions`.
- **Replace:** `{"marketId","customerRef","marketVersion","instructions":[{"betId","newPrice"}]}`.
- **No resubmission:** each `customerRef` and `customerOrderRef` is used once and never reused. A new attempt means a new intent with new refs, and it is possible only after the market is resolved. Betfair's 60 s de-dupe window is a backstop only.

### 9.4 Order lifecycle state machine
**States:** `RECORDED, REFUSED, SUBMITTING, EXECUTABLE, EXECUTION_COMPLETE, FAILED, UNKNOWN, ABSENT_UNCONFIRMED, ABSENT_ACCEPTED, LAPSED, CANCEL_PENDING, REPLACE_PENDING, REPLACED, SETTLED, VOIDED`

- **Terminal:** `REFUSED, FAILED, ABSENT_ACCEPTED, LAPSED, REPLACED, SETTLED, VOIDED`.
- **Unresolved** (blocks the market, or in live mode every market, and counts at full adverse exposure): `SUBMITTING, UNKNOWN, ABSENT_UNCONFIRMED, CANCEL_PENDING, REPLACE_PENDING`, plus any provisional replace child.

**Classifying a place report, per instruction, first rule that matches:**
1. `size_matched > 0`: EXECUTION_COMPLETE or EXECUTABLE, taken from `orderStatus`. Sizes are recorded and `error_code` is kept. If `orderStatus` is missing or invalid, the state is UNKNOWN with the matched size kept as a known minimum.
2. `bet_id` not null, `size_matched` 0 or null, status FAILURE (including `BET_TAKEN_OR_LAPSED`): UNKNOWN (`bet_id_echoed_on_failure`), then confirmed with `listCurrentOrders(betIds=[id])`.
3. Status SUCCESS with `orderStatus` in {EXECUTABLE, EXECUTION_COMPLETE}: that state.
4. Status SUCCESS with any other `orderStatus` (null, PENDING, EXPIRED): UNKNOWN (`unexpected_order_status`).
5. Status FAILURE, `bet_id` null, `size_matched` 0 or null, and a code in a definitive category (`terminal_*`, `market_state`, `planner_bug`): FAILED.
6. TIMEOUT, or any `unknown_outcome` or `unrecognized` code: UNKNOWN.

**At execution level:**
- `PROCESSED_WITH_ERRORS`: classify each instruction.
- FAILURE with a definitive `errorCode` and an empty or missing `instructionReports`: every instruction FAILED with that code.
- TIMEOUT, or an unknown code, with no reports: every instruction UNKNOWN.
- A mismatched ref or count: every instruction UNKNOWN.

**Exceptions:**
- `TransportError` with `may_have_arrived=False`: FAILED (`transport_not_sent`).
- `TransportError` with `may_have_arrived=True`: UNKNOWN.
- `ApiError` in category `session`, `app_key`, `rate_limited`, `planner_bug`, `terminal_account` or `terminal_input`: FAILED (rejected before processing). There is no relogin-and-resend.
- `ApiError` in `unknown_outcome` or `unrecognized`: UNKNOWN.

**Transitions.** Anything else raises `JournalError`.
```
RECORDED         -> REFUSED | SUBMITTING
SUBMITTING       -> EXECUTABLE | EXECUTION_COMPLETE | FAILED | UNKNOWN
UNKNOWN          -> EXECUTABLE | EXECUTION_COMPLETE (found by ref or betId)
                  | LAPSED (found in listClearedOrders LAPSED/CANCELLED)
                  | ABSENT_UNCONFIRMED (§9.7 conditions all met)
                  | UNKNOWN (attempt journaled; attempts++)
ABSENT_UNCONFIRMED -> EXECUTABLE | EXECUTION_COMPLETE | LAPSED (appears later)
                  | ABSENT_ACCEPTED (operator `reconcile --accept REF` after a final clean search; live only)
EXECUTABLE       -> EXECUTABLE (size refresh) | EXECUTION_COMPLETE | LAPSED | CANCEL_PENDING | REPLACE_PENDING
CANCEL_PENDING   -> EXECUTABLE (partial or failed cancel) | EXECUTION_COMPLETE
                  | UNKNOWN (cancel outcome unknown, or BET_TAKEN_OR_LAPSED pending refresh_open_orders(betIds))
REPLACE_PENDING  -> REPLACED (child created with parent_ref/child_ref linked; child EXECUTABLE|EXECUTION_COMPLETE)
                  | EXECUTION_COMPLETE (CANCELLED_NOT_PLACED: remaining cancelled; provisional child -> FAILED)
                  | EXECUTABLE (replace failed; original intact; provisional child -> FAILED)
                  | UNKNOWN (parent and provisional child both unresolved; market halted `unresolved_replace`)
EXECUTION_COMPLETE -> SETTLED | VOIDED
```
A **provisional child** is journaled at replace submit, with its own `customer_order_ref`, side, the new price and the parent's remaining size. Until it resolves it is counted adversarially together with the parent (§10, R8).

### 9.5 Journal (`journal.py`, SQLite)
```sql
CREATE TABLE journal_meta (key TEXT PRIMARY KEY, value TEXT NOT NULL);   -- schema_version, mode, created_at, account_fingerprint
CREATE TABLE events (
  seq INTEGER PRIMARY KEY, event_id TEXT UNIQUE NOT NULL, recorded_at TEXT NOT NULL, monotonic_ns INTEGER NOT NULL,
  kind TEXT NOT NULL CHECK (kind IN ('intent','risk_decision','operator_confirm','submit','report','reconcile',
       'cancel_intent','replace_intent','funds_check','startup_reconcile','halt','resume','kill','settle',
       'probe_result','ref_roundtrip_verified','operator_accept','note')),
  mode TEXT NOT NULL CHECK (mode IN ('paper','live')),
  intent_id TEXT, customer_order_ref TEXT, customer_ref TEXT, bet_id TEXT, market_id TEXT, state_after TEXT,
  payload_json TEXT NOT NULL, prev_sha256 TEXT NOT NULL, event_sha256 TEXT NOT NULL);
CREATE UNIQUE INDEX one_intent_per_order_ref ON events(customer_order_ref) WHERE kind='intent';
CREATE INDEX events_ref ON events(customer_order_ref);
-- BEFORE UPDATE / BEFORE DELETE triggers on both tables: RAISE(ABORT,'journal is append-only')
-- journal_meta inserts only; account_fingerprint is set once
-- PRAGMA user_version=1
```
- `event_sha256 = canonical_sha256({every column except event_sha256, with payload parsed})`. The first event uses `prev_sha256 = "0"*64`.
- On open: `PRAGMA journal_mode=WAL`, `synchronous=FULL`, `fullfsync=ON`, `checkpoint_fullfsync=ON`. A test asserts the last two.
- Every `append` runs inside `BEGIN IMMEDIATE`. It reads the last `event_sha256` and `seq` inside that transaction, then commits before returning. That is why `submit` returns before any network write, and why appends from several processes cannot fork the chain.
- `append` calls `secret.refuse_forbidden(payload)` and `secret.assert_clean(payload_json)`.
- On open the schema is checked: `user_version`, the tables, the triggers, and `meta.mode` equal to the requested mode.
- `verify()` recomputes the whole chain.
- `anchor()` returns the first event's sha, the last seq and the last sha.

### 9.6 `fold()` output (the state given to RiskGuard)
```
{"orders": {customer_order_ref: order_record},
 "halted": bool, "halt_reasons": [str],
 "unresolved_markets": [market_id],
 "submitted_instruction_wall_ns": [int],          # every submitted place/replace instruction, whatever its outcome (R6)
 "transactions_by_clock_hour": {"YYYY-MM-DDTHH": n},
 "orders_today": n, "realized_today_pence": int|None, "unsettled_matched_liability_today_pence": int,
 "strategy_refs_seen": [str], "ref_roundtrip_verified": bool,
 "last_submit_wall_ns": int|None, "consecutive_unknown": n, "clock_regression": bool,
 "funds": {...}|None, "funds_checked_at": str|None,
 "exchange_floor": {"orders_today": n, "realized_today_pence": int|None}|None}   # from the latest startup_reconcile event
```
- **Rate windows** count events with `recorded_at > now − window`, with no upper bound, using `receipts.parse_utc_ns`.
- If `max(recorded_at) > now + 5 s`, then `clock_regression = True`, which means HALT.
- The guard uses `max(journal, exchange_floor)` for `orders_today`, and the worse of the two for `realized_today_pence`.

### 9.7 Reconciliation (live)
`reconcile_unknown` runs straight after an UNKNOWN outcome, during `open()`, and when the `reconcile` command is run. One call blocks for at most about 40 s; attempts are persisted.

1. **Window.**
   - `t_obs` = the time the outcome was observed (`outcome_observed_at`, wall and monotonic).
   - `deadline = max(submitted_at + window_s + grace_s, t_obs + window_s)`.
2. **Polling.** Every `poll_interval_s`, call `listCurrentOrders(customerOrderRefs=[ref], marketIds=[m], orderProjection="ALL")`.
   - A poll counts only if it returned a parsed result with no error.
   - A found order takes its state and sizes from the response, and reconciliation ends.
   - Any read error leaves the order **UNKNOWN**. A read error never counts as "not found".
3. **Ref-independent search.** After the deadline, call `listCurrentOrders(marketIds=[m], customerStrategyRefs=[ours], dateRange={"from": iso(t0 − 5 s)}, orderBy="BY_PLACE_TIME", orderProjection="ALL")`. Any order on the same selection, side, price and size whose betId the journal does not know means: keep UNKNOWN and HALT with `unattributed_candidate_order`.
4. **Cleared orders.** Call `listClearedOrders(betStatus=LAPSED, then CANCELLED, customerOrderRefs=[ref], settledDateRange.from=t0 − 60 s)`. `groupBy` is not sent. Found means LAPSED.
5. **ABSENT_UNCONFIRMED** is reached only when all of these hold:
   - at least `min_successful_polls` (3) successful polls after `t_obs`, spanning at least `window_s`;
   - every poll in the final 5 s succeeded;
   - the step-3 and step-4 queries succeeded and came back empty.

   ABSENT_UNCONFIRMED stays unresolved and keeps full adverse exposure (§10). It never re-places.
6. **ABSENT_ACCEPTED** happens only through `reconcile --accept REF --mode live --confirm-live TOKEN`. The operator must echo `ACCEPT ABSENT <ref>`, and a final step-2 to step-4 pass must be clean. The command appends `operator_accept`.
7. **Unknown cancel:** check by `listCurrentOrders(betIds=[id])`.
8. **Unknown replace:** check the parent by betId. Look for the child by its provisional ref, then with the step-3 search at the new price and the remaining size.
   - A unique match is accepted with the flag `inferred_child_match`.
   - No match or several matches keep the market halted until `reconcile --accept`.

**Settlement** (`settle_from_cleared`):
- Fetch SETTLED and VOIDED BET-level items for our refs since `since_utc`, plus `groupBy="MARKET"` SETTLED items for the actual `commission`.
- Runner results come from a single-id CLOSED `listMarketBook`.
- Our own P&L (`pnl.order_pnl_pence`) uses side, matched price, `sizeSettled` and the runner result.
- The value used is `min(own, betfair_profit)` when both are present.
- A difference above 1p means HALT `pnl_basis_mismatch`.
- If any input is missing, the realised loss for those orders is their matched liability, the worst case.

### 9.8 Kill switch
**Engage.** `kill` (either scope), or `touch` on `STATE_ROOT/KILL`.
1. `killswitch.engage(paths, reason)` writes the file with no lock and no login. It then appends `kill` and `halt` events to the live journal; `BEGIN IMMEDIATE` makes this safe even while another process holds the gateway lock.
2. From that point, every place, replace and probe is refused (R1), including in other processes. The gateway re-checks the file after journaling `submit`, immediately before `send_order`, and again after every report.
3. If `kill_cancels_own_orders` is set, acquire the gateway lock, waiting up to `order_deadline_s + 5` s. Then log in with an emergency login (this skips the successful-login cap but respects a ban and the failure cap). If login fails, exit 3 with `kill_incomplete_no_session` and tell the operator to cancel on the website or in Bet Angel.
4. **Target set**, the union of:
   - `listCurrentOrders(customerStrategyRefs=[config ref] ∪ strategy_refs_seen, orderProjection="EXECUTABLE")`;
   - `listCurrentOrders(betIds=<every non-terminal betId in the fold, including replace children>, orderProjection="EXECUTABLE")`, in batches of at most 250;
   - `listCurrentOrders(orderProjection="EXECUTABLE", includeSourceId=True)` filtered in memory where `sourceIdKey == live_app_key.reveal()`. This leg is skipped with a note if the field is absent. `sourceIdKey` is stripped from every stored record.
5. Cancel by explicit betIds, market by market, at most 60 per request, one request at a time.
6. **Verify** by re-running all three legs.
   - If any order is UNKNOWN or SUBMITTING, or `last_submit_wall_ns` is within the last 20 s, repeat the sweep at `last_submit + 20 s` and again at `last_submit + 30 s`.
   - If there is any EXECUTABLE hit after the final pass, or any read failure, the result is `kill_incomplete`: the HALT stays and the command exits 3.
   - Otherwise the result is `kill_complete`.
7. **Account-wide kill.**
   - Requires `kill --scope account --confirm-account-wide` plus a tty echo of `CANCEL ALL UNMATCHED ON ACCOUNT INCLUDING BET ANGEL STOPS`.
   - Sends one `cancelOrders` with no marketId and no instructions.
   - Never sent concurrently: it runs under the gateway lock and is refused if an earlier account-wide `kill` event has no report.
   - It is not the default. The docs warn that it removes Bet Angel's hedging and stop orders.
8. **Limit.** Matched bets cannot be undone; the docs say so explicitly.

**Resume:**
- The operator removes the kill file by hand.
- Live: `resume --mode live --confirm-live TOKEN` with a tty echo of `RESUME LIVE`.
- Paper: `resume` with no token.
- Resume appends a `resume` event that clears the journal HALT. It refuses if `kill_engaged` is still true.

**Automatic HALT triggers (live):**
- `terminal_account`;
- `terminal_input` (journaled as `validator_gap`);
- `planner_bug` on an order call;
- `app_key`;
- `unrecognized`;
- unexplained account exposure (R12);
- `kill_incomplete`;
- 3 consecutive UNKNOWN outcomes;
- `pnl_basis_mismatch`;
- `clock_regression`;
- `foreign_strategy_order`;
- `unattributed_candidate_order`;
- `unresolved_replace` (that market only, until reconciled).

### 9.9 Startup exchange reconciliation and journal anchor (live)
**At every live `open()`:**
- **Anchor check (A13):**
  - If a Keychain anchor exists and the journal file is missing, the genesis differs, or `seq` is below the anchor's seq, refuse with `journal_anchor_mismatch`.
  - If no anchor exists but the journal has live events, refuse with `journal_anchor_missing`.
  - There is no override in v1. Recovering means deliberately deleting the Keychain item by hand, which the docs explain.
- **`startup_reconcile`** (`since_utc` = today at 00:00Z):
  - `iter_current_orders(customerStrategyRefs=<config ref ∪ strategy_refs_seen>, orderProjection="ALL", dateRange={"from": since}, includeSourceId=True)`;
  - `iter_cleared_orders(SETTLED|LAPSED|CANCELLED, settled_from_utc=since, customerStrategyRefs=..., includeSourceId=True)`;
  - plus the `sourceIdKey == live key` leg from §9.8.
- **Foreign orders.** Any order the journal does not know, matched by `customerOrderRef` or betId, gives HALT `foreign_strategy_order`, and A17 fails.
- **Exchange floor.** `exchange_orders_today` and the realised P&L are journaled in a `startup_reconcile` event and become `exchange_floor`.
- **After every live command:** `anchor_write(profile, journal.anchor() + updated_at)`.

### 9.10 `live-probe` (the only way to set A19)
- Fixed order: `LAY £1.00 @ 1.01` on a selection Yu chooses. Maximum loss if matched is £0.01, because liability = 1.00 × 0.01.
- It passes every rule except V13, from which it is exempt. Caps are unchanged.
- Flow:
  1. place, with a tty echo of `PROBE <market> <selection> LAY 1.01 1.00`;
  2. cancel by betId immediately;
  3. `listCurrentOrders(customerOrderRefs=[ref])` and check the order is found;
  4. `listClearedOrders(CANCELLED|LAPSED, customerOrderRefs=[ref])` (T10 observation);
  5. write raw responses to `live-tests/probe-<ts>/`;
  6. append `probe_result`, and, only if step 3 found the order by its `customerOrderRef`, `ref_roundtrip_verified`.
- With `--replace-step`, before cancelling it replaces to 1.02 (liability £0.02) to observe whether the child inherits the refs (T11). The child is then cancelled.

## 10. Risk guard rules
All money is in integer pence and all prices in integer hundredths. `evaluate_*` is pure: the same inputs give the same output. Rules are checked in the order below. The first failing rule is reported as `rule`, and `detail.failures` lists every failing rule.

**Place** (each instruction, then the request as a whole):
- **R1 `halted`**: the kill file is engaged (fail-closed), or the fold is `halted` or `clock_regression`.
- **R2 `not_armed`** (live): `arming["failures"]` is non-empty.
- **R3 `unresolved_orders`**: the market is in `unresolved_markets`. In live mode, any unresolved order anywhere also triggers it.
- **R4 `validation:<V-code>`**:
  - **V1** market id matches `^1\.\d{1,12}$`.
  - **V2** `selection_id` is an int > 0, `handicap == 0`, and the selection is present in the book's runners.
  - **V3** side is BACK or LAY.
  - **V4** price is exactly on the CLASSIC ladder. There is no implicit snapping.
  - **V5** size has exactly 2 dp, `min_stake ≤ size`, and the minimum is at least £1.00. Sub-£1 stakes are unsupported in v1.
  - **V6** persistence is LAPSE.
  - **V7** instruction count ≤ `min(max_instructions_per_request, 200)`.
  - **V8** no self-match: a LAY price must be below every BACK price on the same selection (and the reverse), across this request plus our EXECUTABLE and unresolved orders.
  - **V9** market gates:
    - status OPEN;
    - runner ACTIVE;
    - `inplay` False (always required in v1);
    - `version` not null;
    - `betting_type` ODDS;
    - `number_of_winners` 1;
    - `market_type` and `event_type_id` in the config lists;
    - ladder CLASSIC;
    - `catalogue_present` (else `catalogue_missing`);
    - `invalid_reason` is null.
  - **V9b** (live): `market_time` is present and `0 < market_time − now ≤ max_minutes_before_off` (else `market_time_too_far` or `market_time_passed`).
  - **V10** book age:
    - live: the A18 conditions;
    - paper: age ≤ `paper.max_snapshot_age_s` against simulation time.
  - **V11** refs: `customerRef` ≤ 32 characters from `[A-Za-z0-9:\-._+*;~]`; `customerOrderRef` ≤ 32 characters from `[A-Za-z0-9-]`; strategy ref ≤ 15 characters.
  - **V12** currency is GBP.
  - **V13** `ticks_between(price, reference) ≤ max_price_deviation_ticks`. The reference is the best back price for a BACK, the best lay price for a LAY, otherwise ltp. With no reference: `no_reference_price`. A probe is exempt.
  - **V14** `profit_ratio_ok`: compute the exact backer profit `size × (price − 1)` in hundredths of a penny, and round it to the penny both half-up and half-even. Refuse if either ratio is below 0.80 or above 1.25. The rule is from F39; the rounding mode is inferred.
- **R5 `stake_cap`**: size ≤ `max_stake_per_order`. For a LAY, `size × (price − 1)` ≤ `max_liability_per_order`.
- **R6 `rate_minute|rate_hour|rate_day`**: every **submitted** place or replace instruction counts, whatever its outcome. Count those in the last 60 s or 3600 s, or the current UTC day, plus this request; the total must be ≤ the cap.
- **R7 `transactions_hour`**: transactions in the current UTC clock hour plus this request must be ≤ `max_transactions_per_hour`. Counting:
  - a placement is 1;
  - a failed placement is 1;
  - a successful cancel is 0;
  - a failed cancel is 1;
  - a replace is 1, plus 1 if its cancel part fails.
- **R8 `market_exposure`**: with the new instructions added as adversarial unmatched orders, `worst_case_market_loss ≤ max_market_exposure`.
  - **Outcomes** O = the book's runners ∪ every selection we hold any order on (even if missing from the book) ∪ {other}.
  - **P&L of order k at outcome o:**
    - BACK: `+s(p−1)` if o is the selection, else `−s`;
    - LAY: `−s(p−1)` if o is the selection, else `+s`.
  - **Matched portions** are counted exactly, at the average matched price.
  - **Adversarial portions** contribute `min(0, pnl_k(o))` at full remaining size. These are unmatched portions and orders in SUBMITTING, UNKNOWN, ABSENT_UNCONFIRMED or CANCEL_PENDING.
  - **A REPLACE_PENDING parent together with its provisional child** contributes `min(parent_adverse(o), child_adverse(o))` for each outcome.
  - `L_m = max(0, max_o −Σ_k contrib_k(o))`.
- **R9 `total_exposure`**: Σ `L_m` over every market with open or unsettled orders ≤ `max_total_exposure`.
- **R10 `daily_loss`**: `max(0, −realized_today) + Σ L_m(after) ≤ max_daily_loss`.
  - Profits never extend the budget.
  - Realised P&L comes from §9.7, net of commission, and is the worse of the journal and exchange values.
  - In live mode, an unknown realised value counts as the matched liability of today's settled orders.
- **R11 `funds`** (live): if the stored funds are older than `funds_max_age_s`, refresh them with `getAccountFunds` (journal `funds_check`). Required stake = Σ(BACK size + LAY size × (p − 1)), and it must be ≤ `availableToBetBalance − funds_reserve`.
- **R12 `unexplained_account_exposure`** (live): `external = abs(api.exposure) − Σ L_m(before)`. The value is always journaled. If `external > external_exposure_tolerance`, HALT and refuse. There is no `warn` policy. The sign of the exposure field is unverified (T7), hence `abs()`.

**Replace:**
- R1, R2 (token mandatory in live), R3 (global in live) and R4 (V1–V14 and V9b on the **new** price, against a fresh self-fetched book) are evaluated first.
- Then R5–R12 are evaluated for both outcomes:
  - (a) the original order stays (its cancel fails);
  - (b) the remaining size is re-placed at the new price.
- R8–R10 use `max(L(a), L(b))`. R6 and R7 count one placement.

**Cancel:**
- Always allowed while halted or killed.
- Only `validate_cancel` applies: bet ids must be ours, at most 60 per request, one market.
- No rate cap applies beyond the 1000/s vendor ceiling.

**Capability:** `issue()` refuses unless `decision["approved"]` and mode is live. TTL is 5 s. The capability is bound to the body sha256.

**Properties the tests require** (§14):
- no sequence of gateway calls leads to an accepted place that breaks R5–R10, measured after acceptance with adversarial settlement;
- the rate windows hold at every instant;
- after a kill there are zero accepted places;
- rebuilding the guard from the journal gives identical decisions;
- every order RPC seen by the fake transport matches exactly one consumed capability and one journal `submit` with the same body sha;
- UNKNOWN and ABSENT_UNCONFIRMED orders are never counted as zero exposure.

## 13. Paper fill model `paper-v1`
Parameters come from `orders.paper` and the model is deterministic: integer pence and hundredths, no randomness, sorted report keys.

1. **Time basis.** `pt` for recordings, `observed_at` (parsed with `parse_utc_ns`) for REST snapshots. An order becomes active at `t_a = t_submit + submit_latency_ms`.
2. **Book at activation.** The latest snapshot with time ≤ `t_a`. If it is older than `max_snapshot_age_s`, or `invalid_reason` is set, the order is REFUSED with `paper_book_stale` or `paper_book_invalid`. Delayed data therefore needs an explicit, labelled relaxation of the age limit.
3. **Gate.** Status OPEN, not in-play, runner ACTIVE. Otherwise `paper_rejected_market_state`, which follows the `market_state` FAILED path.
4. **Immediate match:**
   - A BACK at p walks the `back` levels (availableToBack) with price ≥ p, best first.
   - A LAY at p walks the `lay` levels (availableToLay) with price ≤ p.
   - Each level fills `min(remaining, floor_pence(level_size × displayed_size_fraction))` at that level's price, which is price improvement.
   - Nothing fills beyond the displayed depth.
5. **Resting queue.**
   - A resting **BACK** at p joins the unmatched backs shown in the **`lay`** (availableToLay) ladder at p.
   - A resting **LAY** joins the **`back`** ladder at p.
   - If p is inside the displayed range of that ladder, `queue_ahead` = the displayed size at p, or 0 if p is not shown.
   - If p is beyond the displayed range, `queue_ahead = unknown` and the order never fills passively (`passive_fill_blocked_queue_unknown`).
6. **Passive fills** (`trd_queue_conservative`):
   - Only between consecutive OPEN snapshots: `Δ = traded[p]_now − traded[p]_prev`.
   - A negative Δ, or a settlement-zeroing frame (§2.14), is ignored and flagged.
   - `consumed = Δ / traded_volume_divisor` (default 2: the PRO basis counts backer's stake × 2; this is unverified for the live API and under-fills on purpose).
   - Consumed volume reduces `queue_ahead` first, then fills our order at p.
   - Cancellations ahead of us never improve our position. There are no trade-through fills.
   - With no `traded` data there are no passive fills (`passive_fill_unavailable_no_trd`).
7. **Lapse.** Unmatched size lapses at the first snapshot with `inplay=true`, when the runner is removed, or when `version` changes while the market is SUSPENDED (used as a stand-in for a material change). A plain suspension keeps the order but blocks fills. Ladders are empty while suspended and refresh from new data after reopening.
8. **Settlement:**
   - From a CLOSED market definition with runner statuses WINNER or LOSER.
   - A REMOVED runner voids its matched bets, and the market is **excluded** from P&L totals (`rule4_adjustment_not_modelled`).
   - More than one WINNER with `number_of_winners == 1` is excluded (`dead_heat_not_modelled`).
   - P&L comes from `pnl.market_realized`. Commission uses `evaluation.settled_market_costs(gross_by_market, commission_rate)`, and `commission_source` is echoed.
9. **Labels.** The report carries `model`, the parameters, input sha256s, the `PAPER_ASSUMPTIONS` text, `key_type`, data freshness and `commission_source`. Delayed input adds `delayed_data_paper_fills_unreliable`.
10. **Unsupported in both paper and live,** so the two modes behave the same: in-play, PERSIST, FOK, minFill, betTarget, MOC/LOC, async, and stakes below £1.

Betfair is the exchange operator, so its pages are `official_*`. "Vendor" means Bet Angel only. `first_person_observation` is our own live-test receipt. "Independently verified" is never used unless someone independent reproduces a result. Paraphrases are at most one sentence each.
